# 概率 MTP 草稿性能测量

2026-09-29，RTX 3060 Ti、Qwen3.5-0.8B、BF16 计算 / FP32 recurrent state，`vllm_env`。
单请求 B1，输入最多 128 tokens、固定生成 64 tokens，temperature=0.8、prefix cache 关闭、双方 eager、编译关闭。
三种模式共用已加载模型；每输入/K/模式预热 1 次、计时 5 次，轮换 baseline、greedy MTP 和概率 MTP 的执行顺序。
每轮共享显式 seed（43～47），轮间更换 seed。Baseline 不记录 MTP target feature。
耗时包含引擎调度、草稿生成、target 验证、拒绝采样与状态提交，无 intrusive 状态探针。

`packed` 为 greedy 草稿；`packed_random` 为概率草稿，实际 q 经 FP32 softmax 后按温度采样。
以下比值为普通 eager decode 耗时中位数 / 对应 MTP decode 耗时中位数，**大于 1 表示 MTP 更快，小于 1 表示更慢**。
Prefill 产生的首 token 不计入 decode，decode 段实际产生 63 tokens。所有测量的最终输出长度均为 64。
随机域与浮点路径不同，所有投机样本均与配对 baseline 输出不同，因此这些是实际运行耗时比，不是同轨迹加速证明。

## 本轮概率 MTP 最佳 K 的观测（不构成独立调参验收）

| 输入 | K | 接受率 | 普通 / 概率 MTP decode (ms) | 端到端耗时比 |
|---|---:|---:|---:|---:|
| 英文自然语言 | 2 | 54.9% | 891.92 / 839.19 | 1.062× |
| 中文自然语言 | 4 | 32.5% | 889.80 / 920.76 | 0.967× |
| 仓库代码 | 4 | 39.9% | 875.68 / 817.85 | 1.068× |
| 长记录 | 4 | 79.3% | 877.63 / 474.61 | 1.804× |
| 低匹配输入 | 2 | 55.1% | 885.57 / 862.33 | 1.026× |

长记录 K=4 是本轮收益最明显的负载：decode 耗时比 1.849、整段生成耗时比 1.804，接受率 79.3%；5 轮配对 decode 耗时比为 1.395～1.988。
中文所有 K 都未获收益，英文 K=4 与低匹配 K=1/4 也出现回退。少量百分比的收益有明显轮间波动，不能据此宣称稳定加速。
在相同 K 下，概率草稿相对 greedy 草稿的观测耗时更短，但输出轨迹不同，不能仅归因于 softmax 采样本身。
当前不建议统一把候选数改为 4，也不改变默认 greedy/packed_guarded 配置。

这组结果未覆盖 B4、普通 FULL CUDA Graph baseline、长输出或完整质量预算；不能与 CUDA Graph 加速比相乘。
此前 MTP-1 的 1.03～1.26 耗时比是在 target temperature=0、不同输入/输出长度下测得，与本轮不是同一实验。

复现命令见 [benchmark 指南](../benchmarks/README.md)，原始样本：`logs/bench/mtp_random_fair.json`；测量脚本为 `benchmarks/bench_spec_decode.py`。
